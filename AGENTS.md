- Use npm and keep `package-lock.json` synchronized with dependency changes.
- Use Oxlint and Oxfmt as the only linting and formatting tools; their root config files own code style.
- Treat `.adonisjs/` and `types/db.ts` as generated code. Regenerate them with `node ace codegen` and `npm run db:codegen`.
- Keep delivery dependencies pointing from `app` to `src`; application modules never import from `app` or `inertia`.
- `inertia/components/ui/` holds shadcn components copied from the registry: never reformat, lint or clean them, only adapt an import path.
- Identifiers, file names, URL segments and comments are in English; every text a user sees is in French.
</critical>

## Architecture

Read [the application architecture](docs/architecture/application.md) before adding or refactoring controllers, Actions, Queries, repositories, domain objects, or capability boundaries.

Read [the glossary](CONTEXT.md) before naming or changing domain concepts.

Use Kysely with Postgres for persistence. Keep database invariants in migrations and persistence mapping inside repositories. Prefer explicit read models for non-trivial reads and domain objects for command paths that enforce business rules. Every primary key is a cuid2 generated by the application through an `Identifier` subclass.

## Capabilities

`identity` (accounts, MCP tokens), `inventory` (the pantry), `recipes` (the library) and `cooking` (shared sessions) each have their `app/<capability>` delivery slice and `src/<capability>` core. `app/mcp` is delivery only: it adapts the MCP SDK to the same Actions and Queries, one stateless server per request bound to the token owner.

## Interface

Pages live in `inertia/pages`, built with the shadcn components of `inertia/components/ui` (Base UI, `cva`, `cn`) and the Kraft Rustique theme of `inertia/css/app.css`. Use `Link` and `Form` from `@adonisjs/inertia/react` with a typed `route`. React Compiler is on: no `useMemo`, `useCallback` or `memo`.

## Verification

Run `npm run lint`, `npm run format`, `npm run typecheck`, and `npm test` before committing. Tests need the local Postgres and a `my_kitchen_test` database. Use Conventional Commits, in English.
