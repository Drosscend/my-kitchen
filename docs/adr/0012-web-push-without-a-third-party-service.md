# Web push without a third party service

Alerts also reach the devices a user added from the account page, through the standard Web Push protocol: the browser subscribes with the application's VAPID public key, the server signs and encrypts each message with `web-push` and posts it to the push service of the browser (Google, Mozilla, Apple). No notification provider sits in between and no account is needed anywhere. `web-push` stays on 3.6, the mature line with `@types/web-push`; the 4.0 rewrite was a few weeks old and ships no types. The VAPID pair lives in the Dokploy environment and must never change: every subscription is bound to the public key, so a new pair silently drops all devices. Push stays off, and hidden from the account page, until both keys are set, like Google sign-in. The service worker of the installable app shows the message and opens its page on tap; iPhone and iPad only offer push to that installed app. Push settings default to on and only apply once a device exists, so the first device starts receiving both alerts without extra steps. A push never fails the action that triggered it: a device that answers 404 or 410 is deleted, any other failure is logged.
