# Authorize MCP clients through an embedded OAuth server

Supersedes [0007](0007-personal-tokens-for-the-mcp-endpoint.md). Claude and ChatGPT stopped accepting a static bearer header on custom connectors: they discover an authorization server from the MCP endpoint and run the OAuth 2.1 authorization code flow with PKCE, as the MCP authorization specification requires. The application now embeds that server with oidc-provider, mounted under `/oauth` ahead of the router, and keeps its artifacts in one `oauth_models` table, credential identifiers hashed. Clients identify themselves with a Client ID Metadata Document (Claude, ChatGPT, Claude Code) or register through dynamic client registration; refresh tokens rotate; access tokens are opaque, bound to the `/mcp` resource and checked against storage, so revoking a connection from the account page or deleting the account cuts access at once. The consent page is an Inertia page behind the application session, which decides the account: no second login exists. The `/mcp` route answers 401 with a `resource_metadata` challenge and serves the RFC 9728 document through the helpers of the MCP SDK. Personal tokens are gone rather than kept beside OAuth: no supported client still sends them.
