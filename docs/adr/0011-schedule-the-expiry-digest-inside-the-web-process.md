# Schedule the expiry digest inside the web process

The expiry digest runs once a day at 8 h Paris time. AdonisJS recommends `@adonisjs/queue` for scheduled work, but its drivers need Redis or Lucid, and a worker process beside the web one: the application has neither Redis nor Lucid, and runs as a single Dokploy service. The schedule is therefore a `croner` job preloaded by `start/scheduler.ts` in the web environment only, so tests and Ace commands never start it. Its `protect` option skips a run while the previous one is still going, and the job stops when the application terminates. A single replica keeps the run unique; scaling the web service out would need a lock or a dedicated worker. The work itself lives in the `SendExpiryDigests` Action, which the `notifications:send-expiry` command also calls to send a digest by hand. A run that is missed while the service is down is not caught up: the next one mails everything that changed meanwhile, since each batch is compared with the notice recorded when it was last mailed.
