# Render the indexed pages on the server

Inertia served every page as an empty shell that the browser filled in. Google runs the script, but link previews, Bing and the crawlers of AI assistants read the HTML as it is served, and found neither text nor description. The landing page and the legal notice are therefore rendered on the server, through the Inertia SSR bundle that `node ace build` produces from `inertia/ssr.tsx`, and hydrated in the browser. Every other page keeps client rendering: it sits behind a session or has nothing to rank, and server rendering it would only add constraints. Those pages carry a noindex tag instead, written by the layout when a page has no `seo` props, so `robots.txt` disallows nothing: a crawler must fetch a page to read the tag. The list of indexed pages lives in `config/inertia.ts` and in the sitemap controller, and has to change in both. The structured data and the frequently asked questions of the landing page are written in the page itself, not in a table, since nothing else reads them.
